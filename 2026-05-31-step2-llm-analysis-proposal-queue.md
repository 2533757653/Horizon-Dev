# Step 2: LLM Analysis Engine + Proposal Queue

> **For agentic workers:** This step builds the core LLM-human collaboration layer. ALL proposals generated by the LLM MUST enter the proposal queue and require explicit human approval. There is NO autonomous execution in this step. Do NOT implement auto-execution logic — that is Step 3.

**Goal:** Integrate the Anthropic Claude API to generate trade proposals based on market analysis. Build a technical indicator calculation pipeline. Implement a database-backed proposal queue with a full state machine (`proposed` → `approved` → `executed` / `rejected` / `expired`). Expose proposal management REST endpoints. Add a proposal queue view to the dashboard where humans can review LLM rationale and approve or reject proposals. Log all LLM analysis interactions for audit.

**Architecture:** The LLM Strategy Engine runs as a background APScheduler job triggered every 8 hours. It gathers market data, technical indicators, portfolio state, and external context; constructs a structured prompt; calls the Claude API; parses the response into `TradeProposal` objects; and enqueues them. The Proposal Queue manages durable state transitions. All REST endpoints and dashboard UI allow human review and approval.

**Dependencies:** Step 1 MUST be fully complete and passing all acceptance criteria before beginning this step.

### Task 2: Technical Indicator Calculator

**Files:**

**Specification:**

#### `internal/indicators/calculator.py`
Must define a class `TechnicalIndicatorCalculator`.

Constructor: `__init__(self, db: aiosqlite.Connection)`.

The calculator must compute indicators from a list of OHLCV candles. Since the exchanges in Step 1 provide ticker data but not historical OHLCV, this implementation must: (1) accept a list of price points (closing prices) as input; (2) compute indicators from those price points; (3) persist results to the `technical_indicators` table.

For Step 2, the price history will be synthesized from the market data cache table. The `compute_for_symbol` method must query the `market_data_cache` table for the last N price records of the symbol and use those as input.

**`async def compute_for_symbol(self, symbol: str, prices: list[Decimal] | None = None) -> TechnicalIndicators`:**

If `prices` is None:
1. Query `market_data_cache` for the symbol across all exchanges, ordered by `recorded_at DESC`, limit 50.
2. Extract `last_price` values into a list of `Decimal`.

If fewer than 20 price points are available:
1. Generate synthetic price history using a deterministic seeded random walk starting from the latest price. The random walk must have mean 0 and standard deviation of 1% of the price.
2. This ensures indicators can be computed even with limited historical data.

Then compute:
- **RSI(14):** Standard Wilder's RSI. Formula: `RSI = 100 - (100 / (1 + RS))` where `RS = avg_gain / avg_loss` over 14 periods. Use smoothed averages (Wilder's method).
- **EMA(20) and EMA(50):** Standard exponential moving average with smoothing factor `k = 2 / (N + 1)`.
- **MACD:** `MACD_line = EMA(12) - EMA(26)`. `MACD_signal = EMA(9) of MACD_line`. `MACD_histogram = MACD_line - MACD_signal`.
- **Bollinger Bands(20,2):** Middle band = SMA(20). Upper = middle + 2 * stdev(20). Lower = middle - 2 * stdev(20).
- **ATR(14):** True Range = max(high-low, abs(high-prev_close), abs(low-prev_close)). ATR = smoothed average of TR over 14 periods. For this simplified implementation, use the price range as proxy: `TR = abs(price[t] - price[t-1])`.

Must define a dataclass `TechnicalIndicators`:
- `symbol: str`
- `rsi_14: float | None`
- `macd_line: float | None`
- `macd_signal: float | None`
- `macd_histogram: float | None`
- `ema_20: float | None`
- `ema_50: float | None`
- `bollinger_upper: float | None`
- `bollinger_lower: float | None`
- `atr_14: float | None`
- `computed_at: datetime`

**`async def save(self, indicators: TechnicalIndicators) -> None`:**
1. Insert into `technical_indicators` table.
2. On `IntegrityError` (duplicate `symbol, computed_at`), update the existing row instead.

**`async def get_latest(self, symbol: str) -> TechnicalIndicators | None`:**
1. Query the most recent row for the symbol.
2. Return `TechnicalIndicators` or `None`.

**`async def get_history(self, symbol: str, limit: int = 100) -> list[TechnicalIndicators]`:**
1. Query last N rows for the symbol, ordered by `computed_at DESC`.

**Acceptance Criteria for this Task:**
1. `compute_for_symbol` returns a `TechnicalIndicators` object with all fields populated.
2. RSI values are between 0 and 100.
3. Bollinger upper is always >= Bollinger lower.
4. EMA(20) and EMA(50) are computed correctly (can be verified against known values from a fixed price series).
5. Indicators are persisted to SQLite and retrievable via `get_latest`.
6. With fewer than 20 price points, synthetic history is generated and indicators are still computed.

#### `internal/proposals/models.py`
Must define:

Enum `ProposalStatus` with values: `PROPOSED="proposed"`, `APPROVED="approved"`, `REJECTED="rejected"`, `EXPIRED="expired"`, `EXECUTED="executed"`, `AUTO_EXECUTED="auto_executed"`.

Dataclass `TradeProposal`:
All fields from the `proposals` table schema, plus:
- `is_expired(current_price: Decimal) -> bool`: Returns `True` if `status == PROPOSED` AND (`datetime.now() > expires_at` OR `abs(current_price - proposed_price) / proposed_price > price_drift_threshold_pct / 100`).

#### `internal/proposals/queue.py`
Must define a class `ProposalQueue`.

Constructor: `__init__(self, db: aiosqlite.Connection, order_manager: OrderManager, strategy_config: dict)`.

**`async def enqueue(self, proposal: TradeProposal) -> None`:**
1. Insert the proposal into the `proposals` table.
2. Log: "Proposal {id} enqueued: {side} {volume} {symbol} @ {exchange} (confidence: {confidence_score}, risk: {risk_tier})".

**`async def approve(self, proposal_id: str, approved_by: str) -> TradeProposal`:**
1. Query the proposal. If not found, raise `ProposalNotFoundError`.
2. If `status != PROPOSED`, raise `InvalidProposalStateError(f"Cannot approve proposal with status {status}")`.
3. Check expiry: fetch current market price for the symbol. If expired, call `_expire(proposal_id)` and raise `ProposalExpiredError`.
4. Update status to `APPROVED`, set `approved_by`, `approved_at = datetime.now()`.
5. Submit the order via `order_manager.submit_order()` with `source="llm_proposal"` and `proposal_id`.
6. Update `executed_order_id` with the returned order's `order_id`.
7. Update status to `EXECUTED`.
8. Return the updated `TradeProposal`.

**`async def reject(self, proposal_id: str, rejected_by: str, reason: str = "") -> TradeProposal`:**
1. Query the proposal. If not found, raise `ProposalNotFoundError`.
2. If `status != PROPOSED`, raise `InvalidProposalStateError`.
3. Update status to `REJECTED`.
4. Return updated proposal.

**`async def check_expiry(self, proposal_id: str, current_price: Decimal) -> bool`:**
1. Query proposal.
2. If `status != PROPOSED`, return `False`.
3. If `proposal.is_expired(current_price)`: call `_expire(proposal_id)`. Return `True`.
4. Return `False`.

**`async def _expire(self, proposal_id: str) -> None`:**
Update status to `EXPIRED`. Log the expiry.

**`async def start_expiry_scanner(self) -> None`:**
1. Start a background task that runs every 60 seconds.
2. Query all proposals with `status = PROPOSED`.
3. For each, fetch current market price and call `check_expiry()`.
4. Log summary: "Scanned N proposals, expired M".

**`async def get_proposals(self, status: ProposalStatus | None = None, limit: int = 50) -> list[TradeProposal]`:**
1. Query `proposals` table with optional status filter.
2. Order by `created_at DESC`.
3. Return list of `TradeProposal`.

**`async def get_proposal(self, proposal_id: str) -> TradeProposal | None`:**
Query single proposal by ID.

**`async def get_stats(self) -> dict`:**
Return counts by status: `{"proposed": N, "approved": N, "rejected": N, "expired": N, "executed": N}`.

Must define exceptions: `ProposalNotFoundError`, `InvalidProposalStateError`, `ProposalExpiredError`.

**Acceptance Criteria for this Task:**
1. `enqueue` inserts into `proposals` table.
2. `approve` transitions status `PROPOSED` → `APPROVED` → `EXECUTED` and submits an order.
3. `approve` on non-`PROPOSED` proposal raises `InvalidProposalStateError`.
4. `approve` on expired proposal raises `ProposalExpiredError`.
5. `reject` transitions status to `REJECTED`.
6. Expiry scanner correctly identifies time-expired proposals.
